## 1. 一句话定位

**Bolent 门户 = 可问的智能化诗词体验 + 可信的行业交付背书，按双域名拆内容与商业。**

不是迷你 DXP，不是纯 IT 外包站，也不是只有诗词的内容站。

| 我们是 | 我们不是 |
|--------|----------|
| 垂直 composable 门户 | Liferay 式企业 DXP 平替 |
| 文化 IP 驱动的智能站 | 通用建站模板换皮 |
| 诗词 / AI 为核、资质为翼 | 功能清单越长越好 |

叙事线归属：`bolent-content`（与 JobFirst 首屏分离，见双仓指引）。

## 2. 三层主叙事（有主次，不并列喊）

```
┌─────────────────────────────────────────┐
│ 主叙事 · 文化智能（体验与差异化）         │
│ 诗词库 + RAG 问答 + 人文品牌             │
├─────────────────────────────────────────┤
│ 辅叙事 · 行业信任（获客与背书）           │
│ HarmonyOS / 昇腾 ISV / 案例与服务        │
├─────────────────────────────────────────┤
│ 骨架 · 双线（合规与商业通道）             │
│ .cn 内容体验  ↔  .com.cn / API 商业     │
└─────────────────────────────────────────┘
```

### 2.1 主叙事 · 文化智能（Primary）

| 项 | 内容 |
|----|------|
| **主张** | 门户因「可浏览、可检索、可问答的诗词智能」而值得停留 |
| **证据** | Looma `/v1/poetry/*`、站内 ChatDialog（登录 → consent → ask）、Bolent 文化品牌 |
| **首屏之后的主体验** | `/poetry` 与 AI 对话应是核心路径，不得长期藏在页脚级入口 |
| **成功标准** | 访客能在 1 分钟内理解「这是智能诗词门户」，并完成一次列表浏览或问答 |

### 2.2 辅叙事 · 行业信任（Secondary）

| 项 | 内容 |
|----|------|
| **主张** | Bolent 同时具备鸿蒙生态与昇腾算力侧的可信交付能力 |
| **证据** | 资质徽章（HarmonyOS / OpenHarmony / 昇腾 ISV）、能力卡、案例、关于页背书 |
| **角色** | 为 B2B 咨询与合作背书；**不替代**文化智能成为唯一主标题长期策略 |
| **成功标准** | 商务访客能在 About / Services / 案例中核验资质与能力边界，无需依赖诗词页 |

> 当前首页 hero 仍以「HarmonyOS 生态服务商」为强视觉——属过渡态。中期应让 **品牌 Bolent + 文化智能主张** 与行业背书分层：hero 突出品牌与诗词智能入口，资质徽章保留但不再独占主标题语义。

### 2.3 骨架 · 双线（Infrastructure）

| 线 | 域名 / 入口 | 职责 | 不做 |
|----|-------------|------|------|
| **内容体验线** | `www.szbolent.cn`（个人备案门户） | 品牌、诗词、AI 体验、博客、资质展示 | 不放支付闭环 / 重商业转化主路径 |
| **商业能力线** | `szbolent.com.cn`（企业域，规划）+ `api.genz.ltd`（Looma API） | 认证、支付、套餐、企业接口、小程序合法域名侧 | 不承载诗词内容真相源的第二套 CMS |

双线解决的是 **备案与商业合规**，不是两套互相打架的产品故事。两端共用 Looma 身份与能力，**首屏文案与转化路径分离**。

详情见 [`TENCENT_CLOUD_COMMERCE.md`](./TENCENT_CLOUD_COMMERCE.md)、[`SZBOLENT_COM_CN_CUTOVER_CHECKLIST.md`](./SZBOLENT_COM_CN_CUTOVER_CHECKLIST.md)。

## 3. 页面与模块归属（决策用）

| 模块 | 主归属叙事 | 说明 |
|------|------------|------|
| `/poetry`、ChatDialog、诗人/检索 | 文化智能 | 产品核；优先打磨 |
| Hero 品牌 / tagline | 文化智能（目标态） | 行业词可作副标题或徽章，勿长期独占 H1 |
| 资质徽章、关于「生态资质」、昇腾能力卡 | 行业信任 | 背书层；文案需可核验 |
| `/services`、`/case-study`、`/contact` | 行业信任 | 获客与交付说明 |
| `/blog`（WP） | 文化智能 + 轻信任 | 内容运营；不扩展业务后台 |
| `/pricing`、支付、会员权益 | 双线 · 商业 | **不**挂在个人备案域主转化；走企业域或小程序 |
| Page Engine 菜单/动态页 | 骨架能力 | 编排壳，不自建第二套诗词库 |

## 4. 建站原则（自有道路）

1. **一个视口一个主职** — 首屏不要同时堆资质条、案例条、定价条和诗词入口。  
2. **真相源不双写** — 诗词/AI → Looma；菜单/动态页 → Page Engine；博客 → WP；门户只消费。  
3. **资质是翼不是皮** — 昇腾 / 鸿蒙增强信任，不把整站改成通用「生态服务商官网」。  
4. **特色靠收窄** — 宁做「可问的诗词门户」，不做「什么都能办的迷你 DXP」。  
5. **运维托住叙事** — Compose 启停、入口契约、冒烟未产品化前，不扩更多微服务（见学习清单）。

## 5. 对外话术（可复用）

**短版（15 字内气质）：**  
Bolent — 可问的智能化诗词门户。

**中版：**  
Bolent 以诗词智能体验为核心，辅以 HarmonyOS / 昇腾等生态交付背书；内容站与商业 API 分线运营。

**商务版：**  
我们是具备鸿蒙与昇腾侧交付能力的数智团队，同时运营可检索、可问答的诗词智能门户——技术可信，文化可感。

**禁止话术：**  
「企业级 DXP」「一站式数字化中台」「对标 Liferay」——易错位预期，且与当前交付能力不符。

## 6. 近中期落地顺序

| 阶段 | 动作 | 叙事 |
|------|------|------|
| **现在** | 稳住诗词链路与资质展示；文档与双仓契约 | 三层并存，主次写清 |
| **下一迭代** | 强化 `/poetry` 与 ChatDialog 可达性；hero 品牌/文化智能分层 | 主叙事显性化 |
| **双线补齐** | 企业域 / 支付 / pricing 按备案合规上线 | 骨架落地，不混进 `.cn` 主转化 |
| **明确不做** | 用 WP 重建诗词；为叙事再拆一批微服务；宏伟叙事扩 scope | 冻结项对齐执行方向 |

## 7. 验收口径

| 项 | 通过标准 |
|----|----------|
| 主叙事可感知 | 未读 About 也能发现诗词/AI 是核心能力之一 |
| 辅叙事可核验 | 资质与能力出现在固定背书位，无空口号 |
| 双线不打架 | `.cn` 无支付主路径；商业走企业域/API/小程序 |
| 架构不跑偏 | 新功能能归入既有真相源，不新开「第四套 CMS」 |
